=================
Repository Layout
=================

The importable package is everything under ``src/vicar/``. Everything else supports it:
tests, test data, documentation, scripts, and configuration.

::

    rms-vicar/
    ├── pyproject.toml            # Packaging metadata and the configuration of every tool
    ├── requirements.txt          # Contains only "-e ."; dependencies live in pyproject.toml
    ├── .flake8                   # Per-file exemptions for the continuation-line checks
    ├── .stubtest-allowlist       # The modules that deliberately have no stub
    ├── .codespell-dictionary.txt # British-to-American inflections codespell lacks
    ├── .readthedocs.yaml         # ReadTheDocs build: installs the docs extra, runs Sphinx
    ├── codecov.yml               # Coverage upload configuration
    ├── README.md                 # Front page, included into the Sphinx documentation
    ├── CONTRIBUTING.md           # Contribution guide, included into the Sphinx documentation
    ├── CODE_OF_CONDUCT.md        # Code of conduct, included into the Sphinx documentation
    ├── LICENSE                   # Apache License 2.0
    ├── CLAUDE.md                 # Working rules for AI-assisted development
    ├── .claude/                  # Detailed rules and skills for AI-assisted development
    ├── .github/
    │   ├── workflows/            # GitHub Actions: checks and tests, publishing
    │   ├── dependabot.yml        # Weekly updates for the actions the workflows use
    │   ├── ISSUE_TEMPLATE/       # Issue templates
    │   └── pull_request_template.md
    ├── .vscode/settings.json     # Editor settings: 4-space indent, rulers at 80 and 90
    ├── .cursor/settings.json     # The same editor settings for Cursor
    ├── scripts/
    │   ├── setup-venv.sh         # Creates ./venv and installs the dev and docs extras
    │   ├── run-all-checks.sh     # Runs every quality gate; the source of truth for CI
    │   └── read-docs.sh          # Builds the documentation and opens it in a browser
    ├── docs/                     # Sphinx documentation source
    │   ├── conf.py               # The single Sphinx configuration
    │   ├── index.rst             # Root page; includes README.md and the top-level toctree
    │   ├── module.rst            # Public API reference, generated by autodoc
    │   ├── contributing.rst      # Wraps CONTRIBUTING.md
    │   ├── code_of_conduct.md    # Wraps CODE_OF_CONDUCT.md
    │   └── dev_guide/            # This guide, one chapter per file
    ├── src/vicar/                # The importable package
    │   ├── __init__.py           # Public namespace and the user-level overview docstring
    │   ├── __init__.pyi          # Type stub declaring every public class
    │   ├── py.typed              # PEP 561 marker: the stub is authoritative
    │   ├── _version.py           # Written by setuptools_scm at build time; never edit
    │   ├── vicarlabel.py         # VicarLabel and VicarError
    │   ├── vicarimage.py         # VicarImage
    │   ├── _LABEL_GRAMMAR.py     # The pyparsing grammar for label text
    │   └── _DEFINITIONS.py       # Tables describing the VICAR standard
    ├── tests/                    # The pytest suite, flat, named test_<class>_<topic>.py
    │   └── conftest.py           # Shared fixtures: test-data paths, a label, a seeded RNG
    └── test_files/               # Real VICAR files the tests read; never written to

The two private modules keep upper-case names, ``_LABEL_GRAMMAR`` and ``_DEFINITIONS``,
to mark them as tables of constants rather than code. Ruff's module-naming rule is
switched off for them in ``pyproject.toml``.

Each package module begins with a banner comment naming the file, then the module
docstring and the imports. The classes group their methods under banner comments, such
as ``Properties``, ``Indexing Support``, and ``File I/O``, and the public class
docstrings list the methods in each group. Keep a new method in the group it belongs to,
and add it to the list in the class docstring.

The test suite is flat. Each file is named for the class it exercises and the topic, so
the tests of label construction are in ``tests/test_vicarlabel_construct.py`` and the
tests of reading image files are in ``tests/test_vicarimage_read.py``. The tests of the
grammar are in ``tests/test_label_grammar.py``.
